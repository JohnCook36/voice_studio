# Voice Studio – обновления приложения без GitHub-архивов

Реализовано для **облегчённой установки VoiceStudioSetup.exe** в версии **0.2.0a2**. Скачанные веса, профили голосов, библиотека WAV/MP3, проектные файлы и Python/CUDA среды не заменяются при обычном обновлении кода.

## Для пользователя

- Текущая версия всегда видна **в нижней части окна Voice Studio** (и внизу окна первого установщика).
- При запуске в отдельном потоке производится необязательная проверка новых выпусков на официальном GitHub Releases. Если интернета нет, озвучка продолжает работать.
- Кнопка **«Проверить обновления»** внизу окна запускает проверку вручную.
- Если опубликован выпуск с номером выше установленного, показываются текущая и новая версии и размер скачиваемого кода. Скачивание начинается **только после подтверждения пользователя**.
- Архив с исходным кодом скачивается из официального GitHub Release и проверяется: HTTPS URL владельца репозитория, размер, SHA-256 из записи GitHub, формат ZIP, внутренний номер версии, запрет посторонних файлов. Непроверенные ZIP, чужие ссылки и откаты версий отклоняются.
- После загрузки обновление сохраняется в `%LOCALAPPDATA%\VoiceStudio\.update-pending.zip`; **действующая программа и модели не изменяются**.
- После завершения озвучки закрыть приложение и снова открыть прежний `VoiceStudioSetup.exe`. Он повторно проверит SHA-256, сохранит предыдущую версию в `app-src.previous.zip`, установит новый исходный код и откроет новую версию.
- При следующем открытии внизу будет новый номер версии; повторно скачивать CUDA, Python, Qwen или модель не нужно.
- Если обновление повреждено, запуск не должен молча переходить к неизвестному коду. Предыдущий пакет остаётся на месте; отображается ошибка проверки.

## Ограничения

- **Это обновление кода**, а не автоматическое обновление драйверов, системных библиотек, CUDA, PyTorch или весов моделей. Выпуски, требующие новых зависимостей, должны сопровождаться отдельным обновлением setup/runtime и явным согласием.
- Переносимая **4,9 ГБ Portable-сборка** содержит код внутри собственного EXE и таким способом не обновляется: для неё нужна новая проверенная сборка. Рекомендуется лёгкий установщик.
- Текущая версия установщика (до внедрения этого обновления) не имела этой функции: **нужно один раз скачать обновлённый setup**, после чего будущие *совместимые* обновления кода доступны внутри приложения.
- GitHub Actions **Artifacts** автоматически через API не устанавливаются: они временные и могут требовать авторизации. Автообновление опирается исключительно на опубликованные **GitHub Releases**. Пока релизы не выпущены, приложение честно сообщает, что более новых опубликованных версий нет.
- Нет платных серверов и подписок. Для проверки требуется только доступ к GitHub.
- GitHub Release и SHA-256 не заменяют цифровую подпись Windows. Неподписанный EXE по-прежнему может блокироваться Smart App Control.

## Для разработчика – как опубликовать следующую версию

1. Слить проверенную ветку с приложением в `main` после обязательных тестов. 
2. Изменить `__version__` и `pyproject.toml` на следующую версию, например `0.2.0a3`; отразить совместимость окружения в документации.
3. Создать и отправить Git-тег `v0.2.0a3`, указывающий на коммит в `main`.
4. GitHub Actions `.github/workflows/publish-update.yml` проверит историю и номер версии, запустит unit-тесты, соберёт `voice_studio_source.zip` с только *.py и опубликует GitHub Release с контрольной суммой.
5. После публикации GitHub API сообщает наличие нового выпуска; установленная программа увидит его при следующей проверке.

Не выпускать несовместимое с текущей управляемой средой обновление без отдельной процедуры runtime-миграции. Для серьёзных изменений – выпуск обновлённого установщика и диагностическое сообщение.

## Состояние проверки

Код и тесты добавлены в ветку `feature/mvp-voice-core`; GitHub CI – тесты Windows/Linux, запуск PySide6, упаковка установщика. Поведение замены файлов на конкретном ПК с включённым Smart App Control требует практической проверки. **Новых GitHub Releases на момент реализации ещё нет**, поэтому демонстрационное сообщение о доступном обновлении невозможно без первого опубликованного релиза.
