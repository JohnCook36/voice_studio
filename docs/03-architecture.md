# Техническая архитектура (предложение к реализации)

## Стек
- GUI: Python + PySide6; интерфейс не зависит от деталей моделей.
- Локальный оркестратор задач и адаптеры движков на Python.
- PyTorch/CUDA там, где требуется; аудио – soundfile/ffmpeg и самостоятельная проверка лицензий зависимостей.
- Локальное SQLite-хранилище проектов, очереди, фрагментов, лицензий и голосовых профилей. Никаких внешних БД.
- Для каждого движка – отдельное изолированное окружение/worker-процесс, если версии библиотек конфликтуют.

## Слои
1. UI: редактор, библиотека книг, менеджер моделей, панель лицензий, прослушивание и экспорт.
2. Project service: документы, разделение по главам, персонажи, профили голосов, история и настройки.
3. Parser: чтение TXT/DOCX/EPUB, нормализация, директивы эмоциональной разметки.
4. Segment planner: устойчивые ID фрагментов, контекстные окна, длительность пауз, возобновление.
5. Synthesis queue: последовательная загрузка моделей, scheduler GPU/CPU, отмена, retry, состояния.
6. Engine adapters: capability discovery, load/unload, synthesize, voice cloning, style instruction.
7. Audio pipeline: нормализация громкости, бесшовная склейка, WAV/MP3 и главы.
8. License policy engine: проверка разрешений на этапе выбора, генерации и экспорта.
9. Project storage: аудиокеш, reference audio, метаданные воспроизводимости и provenance.

## Контракт адаптера
Каждый TTS-адаптер объявляет: engine_id, checkpoint_id, hash/revision, языки, voice_clone, predefined_voices, style_instructions, emotion_capabilities, speed_control, pause_control, sample_rate, precision/VRAM estimates, provenance/license manifest; предоставляет load, unload, synthesize, validate_audio, get_diagnostics. Отсутствующие функции явно показываются как «не поддерживается», а не имитируются.

## Сегментация и длинные тексты
- Импорт целого документа без искусственного ограничения по символам.
- Предпочтительный стартовый размер фрагмента – примерно 150–400 символов, но динамический по словам, предложениям, ограничениям модели и тегам.
- Не разрезать слова и прямую речь посередине; учитывать сокращения, имена, пунктуацию и главу.
- Передавать нужный контекст для интонации без раскрытия лишнего текста; применять разделение на поддерживаемые моделью фрагменты.
- Сохранять каждый WAV-кусок сразу на диск, записывать состояние и checksum; при ошибке повторять только повреждённый отрывок.
- Ключ кеша: нормализованный текст, роль/голос, параметры, модель+revision+hash, preprocess version, seed при поддержке.
- После правки инвалидировать только затронутые сегменты, не целую книгу. Соединять с проверкой пауз, краёв, loudness и click detection.
- Для десятков часов текста очередь хранить на диске, не в оперативной памяти.

## Работа с 8 ГБ VRAM
- Никогда не загружать несколько тяжёлых моделей одновременно.
- Worker отдельного процесса; последовательный unload; при необходимости выгружать память завершением worker.
- Измерять peak VRAM, RAM, температуру, latency и OOM; на OOM предлагать меньшую модель/настройки, не падать.
- Поддержать безопасный CPU fallback там, где реально реализован; не выдавать его за быстрый.
- Не обещать Qwen 1.7B в 8 ГБ без практической проверки.

## Контракт сохранения
Проект – отдельная папка с project.json, локальной базой/метаданными, относительными ссылками на fragments/, renders/ и voices/. Формат версионируется, обеспечены миграции, атомарная запись и восстановление после сбоя.

## Наблюдаемость
Локальные логи с удалением/маскированием фрагментов текста и имён файлов по умолчанию. Ошибки разделять: зависимости/CUDA, нехватка VRAM, модель/лицензия, чтение файла, качество генерации, экспорт.
